# Персональный Windows-агент

Первый этап проекта: Telegram → ограниченный контекст → Brain → локальная память; Windows-наблюдение работает отдельно и не обращается к LLM. Требования сохранены в [docs/requirements.ru.md](docs/requirements.ru.md), состояние — в [docs/status.md](docs/status.md).

По явному запросу пользователя в локальном `config.local.toml` включён `pc_access = "full"`: PRIMARY может читать локальные диски, записывать UTF-8 файлы, выполнять PowerShell и запускать программы от имени текущего пользователя Windows, получать скриншоты. SECONDARY получает чтение. В примере конфигурации по умолчанию `pc_access = "read"`; переключение прав происходит только через локальную настройку. Модель имеет собственные инструкции и вызывает инструменты через сервис, а не через инструменты Codex. Повышения системных прав и автозапуска нет.

## Быстрая проверка без Telegram

Python 3.12+ и PowerShell, из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m personal_agent doctor --config config.example.toml
.\.venv\Scripts\python.exe -m personal_agent demo
```

`doctor` не подключается к сети. `demo` использует синтетические события и явно помеченный MockBackend. Это проверка интеграции, а не настоящий ответ GPT. В проекте уже создано отдельное окружение `.venv`.

## Настройка Telegram позднее

Локальный бот уже настроен в игнорируемом Git файле `config.local.toml`. Для повторного запуска в фоне:

```powershell
.\Start-PersonalAgent.cmd
```

`Start-PersonalAgent.cmd` запускает PowerShell с политикой `Bypass` только для этого процесса, поэтому не требует менять системную ExecutionPolicy. При желании можно вызвать `.\Start-PersonalAgent.ps1` из уже разрешающей политики. На рабочем столе создан ярлык `Personal Agent.lnk`, который запускает этот `.cmd`. Скрипт читает токен из `C:\Users\nagas\Desktop\bot_api.txt`, передаёт его только через окружение процесса и запускает daemon со скрытым окном. Повторный запуск при действующем PID не создаёт второй экземпляр. Логи и сведения о процессе — в `.state/logs/` и `.state/daemon-process.json`. Этот запуск не регистрирует автозапуск Windows. После перезагрузки скрипт нужно выполнить снова. Настроены project roots этого проекта и существующего NTM-порта; stat polling ограничен 10 000 файлов суммарно, большой проект может быть охвачен частично (это видно в `observer_health`).

Инструкция ниже подходит для ручной настройки другого бота или переноса проекта.

Токен хранится только в переменной окружения. Не вставляйте его в исходники и не отправляйте в чат. Можно скрыто ввести токен в текущем PowerShell:

```powershell
$botSecret = Read-Host 'Токен Telegram-бота' -AsSecureString
$env:TELEGRAM_BOT_TOKEN = [System.Net.NetworkCredential]::new('', $botSecret).Password
```

Чтобы получить ID, напишите боту с каждого из двух аккаунтов любое сообщение, затем явно запустите:

```powershell
.\.venv\Scripts\python.exe -m personal_agent telegram-ids
```

Команда обращается к Telegram, показывает только числовые ID отправителей личных сообщений, ничего им не отвечает и не запускает daemon. Не запускайте её одновременно с другим poller этого бота. Если список пуст, напишите боту и повторите команду.

```powershell
Copy-Item config.example.toml config.local.toml
# В config.local.toml замените primary_id и secondary_id на разные реальные ID.
# Добавьте известные project_roots. Выберите проверенный backend по backend-spike.md.
.\.venv\Scripts\python.exe -m personal_agent run --config config.local.toml
```

По умолчанию используется `codex_subscription`: официальный Codex с существующей авторизацией ChatGPT. Этот backend проверен реальным ответом `PONG` с отключёнными инструментами. Команды `doctor` и `demo` остаются офлайн; для отдельного тестового daemon можно явно выбрать `mock`. Экспериментальный web backend включается только при `backend = "codex_chatgpt_web"` и `web_enabled = true`; он использует Codex CLI как transport к loopback bridge. Его base URL задайте по установленному bridge, не полагайтесь на пример порта. API key OpenAI не требуется. Существующие настройки Codex и bridge не меняются.

Безопасный режим проверен для Codex `0.164.0-alpha.11.1`. Другую версию backend отклонит до обращения к модели; после обновления CLI требуется заново проверить, что исходящий запрос содержит `tools: []`.

У Telegram-агента собственные инструкции и контекст. Локальная граница запроса заново собирает только persona Personal Agent, его пакет данных и явно приложенные изображения; глобальный `AGENTS.md`, память/skills и служебные сообщения Codex до модели не доходят. Подписка используется для авторизации. Старая история остаётся в SQLite, но ответы до обновления не подмешиваются в новый контекст. Проверка: `.\.venv\Scripts\python.exe scripts\verify_backend_isolation.py`; подробности — в `docs/backend-isolation.md`.

Третий ID и сообщения из групп игнорируются. PRIMARY и SECONDARY получают чат и чтение общей памяти. История диалогов выбирается по ID. SECONDARY не может менять настройки и останавливать daemon. `/help` показывает команды, `/status` — расход за день UTC. Во время ответа можно отправить новую инструкцию: предыдущий ответ этого аккаунта отменяется, контекст собирается заново.

Обычный диалог, `/start`, `/model`, `/instructions`, `/capabilities` и `/memory` отвечают через модель. Сервис передаёт реальные настройки, путь памяти и результаты чтения; готовых разговорных ответов и подмены составного вопроса шаблоном нет. Только точные `/status`, `/diagnostics` и `/help` формируют технический отчёт или справку без LLM. Пожелания вроде «отвечай проще, не так строго» сохраняются по аккаунту и восстанавливаются из его истории.

Инструменты доступны модели в каждом сообщении, включая продолжения «давай» и произвольные формулировки. Доступ к чтению охватывает локальные диски, доступные пользователю Windows; точные фразы больше не определяют, получает ли модель инструмент. Модель может пройти четыре последовательных раунда по три операции, получая реальные результаты после каждого. Запись и команды проверяются ActionGate по PRIMARY и локальной настройке. Сохранённый скриншот передаётся повторно с исходным временем. Запрос без пути не подменяется чтением рабочего стола.

`.\.venv\Scripts\python.exe scripts\verify_conversation.py` проверяет настоящую модель на временных файлах: чтение, запись, PowerShell, восстановление после прежнего отказа, повторное прикладывание синтетической картинки. Использует подписку; частный экран и сеть Telegram не задействует. Флаг `--desktop-only` отдельно проверяет исходную проблемную фразу и перечисление настоящего рабочего стола моделью; в консоль выводятся только счётчики.

Доступны также команды наблюдения:

```text
/ls C:\Users\nagas\Desktop
/read C:\проект\README.md
/screenshot
```

Прямые `/ls`, `/read`, `/screenshot` и распространённые формулировки предварительно выполняются сервисом. Остальные запросы модель решает через постоянно доступный протокол инструментов. Специализированное чтение ограничено 100 записями и 32 KB UTF-8, отсекает известные файлы авторизации и сетевые/device paths. В полном режиме PowerShell работает с правами пользователя Windows и способен выполнять произвольные команды; фильтр специализированного чтения не является sandbox для PowerShell. Вывод команд ограничен 16 KB и очищается от распознаваемых токенов/ключей, запись через `write_file` — 256 KB. Команды имеют timeout до 120 секунд; отмена останавливает собственный процесс команды. Дочерней команде не передаются токен бота и API auth env. Содержимое файлов и результатов инструментов передаётся как данные.

Скриншот сохраняется локально и отправляется в Telegram; subscription backend получает его как image input. Следующий вопрос о нём повторно использует файл, даже если первый разбор был отменён. Native Codex tools остаются выключены; PowerShell выполняет отдельный host executor при разрешённом полном доступе. Для Web backend анализ изображения пока недоступен. Защищённые/заблокированные Windows-окна могут быть неполными; GDI-захват ограничен 16 мегапикселями. Фонового потока снимков нет.

`/diagnostics` проверяет состояние daemon, observer, polling, backend и последние ошибки. Код ошибки и безопасное описание сохраняются; сырые provider stderr, токены и HTTP URL в чат не выводятся. Причину исторического сбоя 26.10 в 11:55 восстановить невозможно: старая версия сохраняла только `RuntimeError`.

PRIMARY может отправить точную фразу `АВАРИЙНОЕ ВЫКЛЮЧЕНИЕ` с пробелами по краям. Она обрабатывается до LLM. Обычная остановка — Ctrl+C. В полном режиме PRIMARY может поручать управление приложениями через PowerShell. При служебной отмене daemon завершает собственные процессы транспорта, STT и текущей команды. Автозапуск не регистрируется.

## Память и наблюдение

В `data_dir` создаются `memory/state.sqlite3`, `current/context.md`, `days/`, `projects/`, `attachments/`, `transcripts/` и служебные каталоги. SQLite содержит канонические события, provenance, сообщения, offset polling и метрики. Markdown — представления с IDs свидетельств; их можно восстановить из базы. FTS5 ищет без vector DB. Raw observations на этом этапе не удаляются; compaction с семидневной корзиной будет отдельным этапом после накопления реальных данных.

Windows-датчик читает foreground window, PID/exe/title, процессы и idle time. Файлы в настроенных проектах проверяются ограниченным stat polling, содержимое пассивно не читается и не меняется. Это best-effort наблюдение: оно не обнаруживает все открытые файлы, все кратковременные процессы и точный смысл работы. Низкая уверенность явно отражается в контексте. Нет фоновых screenshots, чтения буфера обмена, keylogging, браузерного управления, Discord capture или фоновых облачных вызовов.

Вложения сохраняются под случайными локальными именами; оригинальное имя — только метаданные. Текстовые документы индексируются в пределах 32 KB; изображения/видео сохраняются без обещания анализа содержимого. Голосовые можно распознавать локальным `whisper.cpp`: укажите пути к `whisper_executable`, `whisper_model` и `ffmpeg_executable`. Модель и бинарники устанавливаются отдельно. Автоматических загрузок и облачного STT нет. Без настройки голосовое сохраняется с явным сообщением, что расшифровка недоступна.

Исходный звук и транскрипции остаются локально. В Brain попадает только ограниченный пакет для явного пользовательского запроса; его передача выбранному backend является частью чата. Оценки токенов приблизительные (`число символов / 4`), это не данные биллинга.

## Источники интерфейсов

- [Telegram Bot API](https://core.telegram.org/bots/api): long polling, private sender IDs, загрузка файлов.
- [OpenAI Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode): официальный CLI transport.
- [HTTPX async](https://www.python-httpx.org/async/): отменяемые HTTP-запросы.
- [whisper.cpp](https://github.com/ggml-org/whisper.cpp): локальная CLI-расшифровка. Реальная точность STT требует проверки с установленной моделью.

Design notes и точные результаты backend/Windows-проверок находятся в `docs/`. Живая Telegram-сессия и распознавание настоящего аудио не считаются проверенными по результатам mock-тестов.
