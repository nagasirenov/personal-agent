# Состояние проекта

Дата: 26 октября 2026. Реализованы Telegram, память, наблюдение и управляемые инструменты ПК. По последнему явному запросу пользователя PRIMARY получил полный доступ от имени пользователя Windows: `pc_access = "full"`. Это изменение прежнего пассивного режима; остальные фазы ТЗ по-прежнему не считаются завершёнными.

## Выполненная проверка

- 46 автоматических тестов прошли, включая live Windows snapshot и завершение собственного тестового дерева процессов.
- `doctor --config config.example.toml` подтвердил Python 3.15, SQLite/FTS5, доступность Windows observer и отключённые действия; сетевых вызовов нет.
- `demo` проверил синтетическую историю, ответ SECONDARY, игнорирование третьего ID и запрет действий; использован Mock, сетевых вызовов нет.
- Итоговый `CodexSubscriptionBackend` получил реальный `PONG` через существующую ChatGPT-подписку, с отключёнными инструментами и без API-ключей в дочернем окружении. Выбран основным backend.
- Живой Telegram: `getMe` подтвердил бота, webhook отключён, daemon получил update и сохранил offset; `last_completed_turn` записан после успешной отправки ответа. Windows observer активен; stderr запуска пуст. Токен остаётся в исходном пользовательском файле и окружении дочернего процесса, в конфигурацию не копировался.
- Автозапуск Windows не настроен. Web bridge generation, удалённая отмена Web-запроса и настоящее STT остаются непроверенными.

## Исправления по первому живому диалогу

- Persona модели задана явно: Personal Agent; Codex используется как transport. ID модели и public rules берутся из настроек сервиса.
- Настройки и пути передаются как факты сервиса. Разговорные заготовки для `/start`, `/model`, `/instructions`, `/capabilities` удалены; диалог формирует модель. Без LLM работают только точные технические команды `/diagnostics`, `/status`, `/help`.
- Пожелания к тону сохраняются по аккаунту, восстанавливаются из аутентифицированной истории; ответы не перегружаются UUID без просьбы.
- `/ls`, `/read` и прямые запросы на скриншот выполняются сервисом; остальным формулировкам модель сама подбирает инструменты. Содержимое файлов и экрана остаётся данными. ActionGate открывает запись/команды только PRIMARY при `pc_access=full`.
- Официальный backend принял image input из синтетической красной картинки и ответил `Red`. Для Web bridge vision не заявляется.
- Старую причину ошибки 11:55 восстановить нельзя. Новые ошибки имеют безопасные коды и описание; сырые credentials/stderr не записываются в чат.
- После изменений прошли 72 теста. Отдельно проверен реальный ответ модели с runtime-контекстом и локальный GDI-захват 2880×1800 с корректным DPI; частный экран в облако/Telegram для проверки не отправлялся.

## Изоляция от Codex AGENTS.md

- Глобальные правила действительно попадали в raw CLI запрос: отключение `config.toml` и project docs не убирало global guidance.
- Добавлен request-local gateway, который формирует запрос к модели только из собственных инструкций и данных Personal Agent. В фактическом egress — 0 совпадений AGENTS/coordinator, одна user-запись и `tools: []`.
- Введён контекст `personal-agent-v2`: старые assistant-ответы исключены из модельного контекста, но история, пользовательские сообщения и предпочтения не удалены.
- Прошли 90 тестов. Реальная генерация текста и анализ синтетического изображения через новую границу подтверждены (`ISOLATED_OK`, `Red`). Проверка не отправляла частный экран и не писала в Telegram.

## Доступ к наблюдениям

- Детерминированный разбор понимает команды `/ls`, `/read`, `/screenshot` и прямые запросы обычным языком. До трёх наблюдений выполняются перед ответом модели. Полный исходный вопрос сохраняется, в том числе просьба объяснить список или обсудить AGENTS.md как документ. Отсутствующий путь требует уточнения; Desktop не подставляется молча.
- Вопрос о папке памяти отвечает модель по runtime facts; путь указывает на `data_dir/memory`. Фиксированные абзацы об идентичности, памяти, инструкциях и доступах удалены вместе с классификатором, который перехватывал такие вопросы.
- Скриншот сохраняется по пользователю. Следующий вопрос «И ты его видишь?» прикладывает тот же файл как image input; если первая отправка/разбор отменены новой инструкцией, снимок не теряется.
- Сохранённые снимки не исчезают из контекста по произвольному 30-минутному сроку: исторический снимок передаётся с исходным временем. Вопрос о том, как сделать скриншот, не разрешает съёмку.
- Специализированное чтение: 100 записей каталога, 32 KB текста, фильтр credential-sensitive файлов и UNC/device paths. В полном режиме PowerShell — отдельная возможность с правами пользователя Windows; фильтр чтения не ограничивает произвольную команду как sandbox. Вывод ограничен 16 KB, распознаваемые credentials очищаются; запись UTF-8 — до 256 KB. Секретные env daemon не наследуются дочерней командой.
- В предыдущем отчёте заявлялись 112 тестов, локальные чтение рабочего стола, GDI-снимок и backend health. Для запуска добавлен `Start-PersonalAgent.cmd`, не меняющий системную ExecutionPolicy; обёртка сохранена.
- После удаления заготовок `scripts/verify_conversation.py` подтвердил на настоящем backend: красная картинка распознана в двух последовательных запросах, отправка фото одна, модельный план прочитал реальный тестовый файл, путь памяти взят из фактов. Пять вызовов модели, без частного экрана и без сети Telegram. Wire-проверка повторно подтвердила отсутствие host AGENTS/coordinator и пустые native tools.
- Итоговый полный прогон после этих изменений: 119 тестов, все прошли. Проверяются ответы модели вместо заготовок, реальные результаты чтения в контексте, сохранение исторического изображения, отмена текущего разбора, изоляция изображений по аккаунту и запрет модельной съёмки по вопросу «как сделать скриншот».

## Полный доступ PRIMARY и регрессия рабочего стола

- Причина последнего отказа подтверждена по production-переписке: фраза «Ну слава богу, скажи какие файлы на рабочем столе есть» не совпадала с direct parser, а tools раньше включались только по определённым словам. Это ограничение удалено: протокол доступен в каждом аутентифицированном запросе, чтение охватывает локальные диски. До четырёх раундов, по три операции; уточнения «давай» используют контекст.
- В локальном конфиге включён полный доступ PRIMARY. Native Codex tools остаются отключены, AGENTS.md не наследуется; PowerShell и запись выполняются сервисом вне транспорта модели. Повышение Windows-прав и автозапуск не настраивались.
- Реальная модель успешно выполнила исходную фразу на настоящем Desktop: получено 60 записей, ответ содержал реальные имена. Тест с временными файлами подтвердил запись и PowerShell; синтетическая картинка и её повторное прикладывание также прошли. Telegram-сообщения для теста не отправлялись.
- Полный прогон: 136 тестов, 135 прошли, один пропущен из-за отсутствия права на создание Windows symlink. Wire-проверка сохранила изоляцию от host AGENTS/coordinator.

## Следующая практическая проверка

1. Бот, два ID, официальный backend и project roots настроены. Для повторного запуска использовать `Start-PersonalAgent.cmd` (или `.ps1` при разрешающей ExecutionPolicy).
2. Проверить личный диалог со SECONDARY. Для большого NTM-проекта учитывать ограничение stat polling: 10 000 файлов суммарно на настроенные roots.
3. Накопить 1–2 часа событий; с обоих аккаунтов спросить о работе и предыдущем дне. Сверить ответ с локальным timeline.
4. При необходимости отдельно установить Whisper и проверить голосовое.
5. Проверить аварийную фразу с PRIMARY. Для возврата к наблюдению установить `pc_access = "read"` и перезапустить daemon.

Никакого автозапуска, изменения глобальной конфигурации Codex, управления браузером или регистрации системных служб при разработке не выполнялось.
